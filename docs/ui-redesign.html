TursoBench UI Redesign

A new layout for the desktop workbench. The connection settles into a title bar, the crowded schema sidebar splits into an activity rail, queries and tables open as tabs, and the floating windows become one docked inspector. The prototype below works: it runs on sample rows shaped like the clip-daemon fixture.

Click a table or a cell Review the 3 staged changes Ctrl K commands F1 shortcuts Commit, then run a query

Sample data only. Nothing here touches a database. Sized as a 1180 px wide desktop window; scroll sideways on narrow screens.

What changes

Every feature in the current build stays. The redesign moves each one to the place where it is used, so the screen shows less at once.

Connection

Before
A permanent top panel with the path field, Open/Close and two checkboxes, visible even while connected.
After
An Open sheet before connecting: access mode cards plus the exclusive-use acknowledgement. Once open, a slim title bar shows the file, a READ ONLY or READ / WRITE badge and the editor transaction state.

Sidebar

Before
Schema, table actions, diagnostics, bookmarks, history, settings and help stacked in one 260 px column with collapsing headers.
After
An activity rail with Schema, History, Saved, Diagnostics and Settings. One panel shows at a time, so the schema tree gets the full height.

Floating windows

Before
Cell inspector, record detail, DDL and table metadata each open a window that covers the grid.
After
A docked inspector with Cell, Record and Structure tabs. It follows the selection and holds staging, references and DDL.

Workspace

Before
Editor, bindings, BEGIN/COMMIT/ROLLBACK, browse paging, filters, export and the grid all in one column, one result at a time.
After
Tabs for each query and each table. A query tab has editor and results; a table tab has filter, grid and pager. Each tab carries only its own controls.

Bindings

Before
One line of tagged JSON, with a button that fills in NULLs.
After
A parameter form built from the placeholders in the SQL, with a type and a value per parameter. Edit as JSON stays available and round-trips.

Staged edits

Before
Text prefixes ✎ and [delete] inside cells, and a preview window.
After
Tinted cells and a gutter stripe per row state, a staged-changes bar that names the count, and a review sheet with the exact SQL and bindings before commit.

Status

Before
One long status sentence, plus outcomes in a collapsing header.
After
A status bar with separate fields for connection, editor transaction, timing and the slow-query badge. Outcomes open in a drawer.

Grid

Before
A button per cell, a · suffix for indexed columns, and column width set from a right-click slider.
After
A real table with PK/IX/FK tags and the declared type in each header, sort arrows, drag-to-resize, type-aware alignment and a NULL style.

Safety rules that stay

  • Read-only by default. Read/write is a separate card in the Open sheet and shows as an amber badge for the whole session.
  • Exclusive use is still confirmed, not enforced. The acknowledgement says so, and Open stays disabled until it is ticked.
  • Discard is not cancel. The Discard button appears only while a request runs, and its tooltip says writes continue.
  • Browsing uses its own connection. The schema panel footer says so, and table tabs never show uncommitted editor work.
  • Exports use retained rows. The export menu names the scope and states that staged overlays are left out and SQL never reruns.
  • Counting is explicit. The schema tree shows no row counts. Count rows sits in Structure and warns that it scans.

Building it in egui

  1. Shell and themeReplace the stock visuals with a Visuals built from these tokens. Add the title bar and status bar with the existing Panel::top/bottom, and move the connect form into a Modal.
  2. Rail and inspectorAdd a SidebarView enum behind a 46 px rail panel. Fold inspector_windows and schema_windows into a right panel with three tabs.
  3. GridSwap the button-per-cell grid for egui_extras::TableBuilder: virtualized rows, sticky header and resizable columns come with it.
  4. TabsThe largest change: split App's single result, browse and active ticket into per-tab state, keyed by ticket so late events land in the right tab.
  5. Palette and parametersA command list over existing actions, and a parameter form driven by sql::parameter_names that writes the same Bindings.
