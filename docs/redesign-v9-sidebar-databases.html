TursoBench · redesign v9 · proposal

One sidebar for every database job

Opening, closing, switching, and searching across and within databases currently happen in eight different places. This proposal puts all of it in the left sidebar: one search box, one list of open databases (each expanding into its own schema), and one list of databases you can open.

2 · Proposed sidebar — try it

This is a working prototype. Click databases, search, open and close. Shortcuts: Ctrl+P or / focuses search, ↑↓ Enter pick a result, Esc clears, Ctrl+PgUp/PgDn cycles open databases. Hover an open row for its close button.

Open databases

Accordion: the active one expands into its schema, the others collapse to one 44px row showing access, transaction and draft state. Slot meter shows the 4-database limit.

Available

Recent plus discovered files that are not open. Clicking one expands an inline access review instead of navigating to a page.

Search

One field. Scope chips: All open (default), This database, Databases. Results are grouped by database; picking one switches and opens the object.

5 · Constraints I found, and how the design handles them

Only one workspace is live

self.database is the active workspace; others sit in self.parked and are swapped with swap_workspace. The sidebar must render parked rows from parked without swapping, and switch only on click. select_workspace is a no-op while a picker, close-confirm or quit is active, so rows disable themselves in those states.

Four-database cap

new_workspace refuses a 5th and only writes to the status text. The slot meter makes the limit visible, and Available rows disable with a reason (“4/4 open, close one”). Reviewing access already occupies a slot today; that stays.

Close acts on the active database

request_close and confirm_close belong to self.database. Closing a background row = select_workspace(id) then request_close(); the confirm is drawn inline under that row from the existing flag. Closing is async (closing), so the row shows a spinner.

Column search needs schema loaded

Columns come from ui.diagram.data, which parked databases may never have loaded. Searching with “All open” should trigger load_diagram for those, and show “columns still indexing” until done. Tables always match.

Width budget

The sidebar defaults to 272px (190px under 900px window width). Four 56px chooser rows plus a tree will not fit, hence collapsed rows (44px / 34px) and one expanded database at a time.

Pending open is already a workspace

request_database creates a blank workspace and sets its path before the Open click. The inline card is just a different view of that pending workspace, so no new state machine is needed.
